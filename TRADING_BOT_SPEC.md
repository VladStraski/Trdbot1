# Trading Bot — Техническое задание

## 1. Цель проекта

Торговый бот для Bybit, бессрочные фьючерсы (linear perpetuals), на основе технического анализа
(индикаторы, осцилляторы, свечные паттерны) с подтверждением через ордербук и рыночный контекст
(funding rate, open interest, long/short ratio). Старт — paper trading на Bybit Demo Trading,
переход на реальную торговлю только после успешного прогона на демо.

## 2. Технологический стек

- **Python 3.11+**
- **pybit** (официальный SDK Bybit) для REST + WebSocket v5 API
- **pandas** + **pandas-ta** (или **ta-lib**, если доступен в окружении) — расчёт индикаторов
- **backtesting.py** или **vectorbt** — бэктест-движок
- **SQLite** на старте (можно перейти на PostgreSQL позже) — хранение сделок, сигналов, состояния
- **python-dotenv** — конфигурация через `.env`
- Опционально: **python-telegram-bot** — уведомления

## 3. Биржа и торговый инструмент

- Биржа: **Bybit**, категория `linear` (USDT-perpetual)
- Режим маржи: **Isolated** (не Cross) — потеря ограничена маржой конкретной позиции
- Старт: **Bybit Demo Trading**
  - REST: `https://api-demo.bybit.com`
  - WebSocket приватные стримы (позиции/ордера): `wss://stream-demo.bybit.com`
  - WebSocket публичные данные (стакан, свечи, сделки) — **общие с mainnet**: `wss://stream.bybit.com`
    (для демо-аккаунта отдельного публичного стрима нет и не нужно)
  - WS Trade API на demo-окружении **не поддерживается** — ордера через demo только по REST
  - Пополнение демо-баланса — эндпоинт `/v5/account/demo-apply-money`
- Переключение demo/prod — **только через конфиг**, код execution-слоя должен быть идентичен для
  обоих окружений (различаются только base URL и ключи)

## 4. Архитектура (модули)

```
Market Data (klines, разные TF) ──┐
Order Book Stream ─────────────────┼──► Strategy Module ──► сигнал ──► Risk Manager ──► Execution
Market Context (funding, OI, ─────┘         ▲                              │
long/short ratio) ─────────────────────────┘                              ▼
                                                                    Position Manager
                                                                    (синхронизация с биржей)
```

**Модули:**

1. **Data Layer** — REST для истории (klines), WebSocket для реал-тайма. Кэш в БД.
2. **Multi-TF Aggregator** — держит синхронизированные буферы свечей на разных таймфреймах,
   пересчитывает индикаторы только по закрытию свечи соответствующего TF.
3. **Order Book Module** — WS-топик `orderbook.{depth}.{symbol}` (для linear глубина до 500).
   Считает: Order Book Imbalance (OBI), стены (крупные заявки), спред, CVD (Cumulative Volume
   Delta по потоку сделок `publicTrade`).
4. **Market Context Module** — funding rate, open interest (`/v5/market/open-interest`),
   long/short ratio — всё нативно из Bybit API, бесплатно. On-chain/новостной сентимент — не в
   MVP, отдельная фаза (требует платных внешних API).
5. **Indicator Engine** — обёртка над pandas-ta.
6. **Strategy Module** — confluence-модель (см. раздел 6), изолирована от биржевого кода —
   принимает данные, отдаёт сигнал.
7. **Risk Manager** — см. раздел 7.
8. **Execution Engine** — превращает approved-сигнал в ордер через API. Единый интерфейс для
   demo/prod, переключение по конфигу.
9. **Position Manager** — синхронизация состояния с биржей через приватный WS + периодическая
   сверка через REST (расхождение = алерт).
10. **Backtester** — использует ту же Strategy Module, что и live-контур. Обязательна защита от
    look-ahead bias (см. раздел 5).
11. **Storage** — БД сделок, сигналов, состояния equity.
12. **Logger / Notifications** — структурированные логи + опционально Telegram-алерты.
13. **Config** — все параметры, ключи (demo и prod — раздельно) через `.env`, никогда не в коде.

## 5. Мультитаймфреймовая модель

Три слоя (по мотивам Triple Screen, параметры — дефолт, настраиваются в конфиге):

| Слой | TF (дефолт) | Роль |
|---|---|---|
| Контекст | 4h | Направление тренда: EMA 50/200, ADX (>20 = есть тренд) |
| Сигнал | 1h | Точка входа: RSI/Stoch RSI, MACD, Bollinger Bands |
| Триггер | 15m | Тайминг: свечной паттерн, swing high/low |
| Микро-триггер | real-time | Ордербук (OBI, CVD), funding rate |

**Критично для бэктестера:** при выравнивании таймфреймов всегда брать последнюю полностью
закрытую свечу старшего TF относительно текущего момента на младшем TF — иначе получится
look-ahead bias и нереалистично хорошие результаты бэктеста.

## 6. Индикаторы, осцилляторы, паттерны

| Роль | Инструмент |
|---|---|
| Режим рынка (тренд/флэт) | ADX |
| Направление тренда | EMA 50/200 |
| Точка входа (momentum) | RSI или Stoch RSI (не оба — дублируют друг друга) |
| Подтверждение тренда | MACD |
| Волатильность / размер стопа | ATR |
| Волатильность / сжатие-расширение | Bollinger Bands |
| Подтверждение объёмом | OBV |
| Динамический уровень цены | VWAP |
| Подтверждение входа (свечи) | Engulfing, Pin Bar/Hammer, Doji (через готовые функции ta-lib) |
| Уровни SL/TP | Swing highs/lows (локальные экстремумы) |

Сложные чарт-паттерны (голова-плечи, треугольники, флаги) — **не в MVP**: плохо формализуются в
код без большого числа ложных срабатываний, отдача несоразмерна сложности реализации.

**Правило генерации сигнала — confluence scoring**, не жёсткое "всё сразу":

```
Обязательный фильтр: направление тренда на 4h (EMA50 vs EMA200, ADX > 20)

Очки (пример для лонга):
  1h RSI выходит из перепроданности          +2
  1h MACD гистограмма растёт                 +1
  15m bullish паттерн на swing low            +2
  15m объём выше среднего (OBV)               +1
  Ордербук: OBI > 0, CVD растёт               +2
  Funding не экстремально положительный       +1 (иначе -2)

Порог входа: сумма ≥ 6 (калибруется на бэктесте)
```

## 7. Risk Management

**Position sizing** — fixed fractional risk, не фиксированная сумма/плечо:
```
risk_amount = equity × risk_pct          # дефолт 0.5-1% на сделку
qty = risk_amount / |entry_price - stop_price|
```

**Стоп-лосс vs ликвидация — разделять всегда.** Дистанция до ликвидации должна быть ≥ 3× дистанции
до стоп-лосса:
```
stop_distance = k × ATR                  # k ≈ 1.5-2
leverage = min(желаемое_плечо, max_leverage_by_liq_safety, hard_cap)   # hard_cap дефолт 5x
```
После открытия позиции — сверять фактическую `liqPrice` из ответа API с расчётной нормой.

**Take-profit / управление позицией:**
- Минимальный R:R на вход — 1.5R
- Частичное закрытие на 1R, остаток — на трейлинге
- Breakeven-стоп после 1R
- Trailing по ATR или по structure (swing lows/highs)

**Portfolio-level circuit breakers** (отдельный слой, проверяется независимо от стратегии):

| Лимит | Дефолт |
|---|---|
| Риск на сделку | 1% equity |
| Суммарный риск по открытым позициям | 3% equity |
| Макс. открытых позиций | 3 |
| Дневной лимит убытка | -3% equity → стоп торговли до конца дня |
| Серия убыточных сделок подряд | 5 → пауза + уведомление |
| Просадка от пика equity | -15% → полная остановка, ручной рестарт |

**Издержки в расчёт R:R:** funding (начисляется каждые 8ч) + maker/taker комиссии — обязательно
учитывать в бэктесте, иначе результат будет завышен относительно реальности.

**Исполнение:**
- SL/TP отправляются на биржу как реальные `reduce-only` ордера сразу при открытии позиции —
  никогда не хранить только "в памяти" бота
- Kill switch: ручной (немедленное закрытие всего) + автоматический (серия API-ошибок, разрыв
  фида цен дольше N секунд, потеря соединения)

## 9. Порядок разработки (этапы)

1. **Data Layer** — подключение к Bybit Demo (баланс, klines), multi-TF агрегатор
2. **Indicator Engine** — расчёт индикаторов на исторических данных, проверка на графике
3. **Order Book Module** — OBI, CVD в реальном времени
4. **Strategy Module** — confluence-логика, пока без реальных ордеров (только сигналы в лог)
5. **Backtester** — прогон стратегии на истории, проверка на look-ahead bias
6. **Risk Manager** — position sizing, leverage, SL/TP расчёт
7. **Execution Engine** — реальные ордера на Demo Trading аккаунте
8. **Position Manager + синхронизация** — устойчивость к разрывам соединения
9. **Portfolio limits / kill switch**
10. **Notifications / мониторинг**

Каждый этап — рабочий и тестируемый сам по себе, не переходить дальше, пока предыдущий не
проверен на реальных (demo) данных.

## 10. Требования к безопасности и надёжности

- API-ключи только через `.env`, никогда не коммитить, `.env` в `.gitignore`
- Ключи demo и prod — раздельные переменные, явное указание окружения в конфиге (не автовыбор)
- Обязательный `reduce-only` для SL/TP ордеров
- Логирование каждого решения стратегии (не только сделок) — для последующего разбора
- Периодическая сверка внутреннего состояния бота с реальным состоянием на бирже через REST
- Reconnect-логика для каждого WS-стрима независимо, с backoff
- Никакой реальной торговли до: успешного бэктеста → успешного прогона на demo в течение
  разумного периода → ручного ревью результатов
